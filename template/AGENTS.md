# TEMPLATE KNOWLEDGE BASE

## OVERVIEW

Canonical generated-project source: a Bun/Turbo workspace with authenticated
Next.js app, public Next.js site, Convex backend, agent runtime, email, UI, setup,
and live QA tooling. Changes here propagate to future generated projects.

## STRUCTURE

```text
template/
├── apps/app/             # Authenticated customer and operator product
├── apps/web/             # Public marketing surface; no Convex runtime
├── packages/backend/     # Contracts, domain config, Convex functions and engine
├── packages/agents/      # Mock/OpenAI agent turn runtime
├── packages/ui/          # Shared Tailwind v4 component subpath exports
├── packages/email/       # Reservation React Email templates
├── scripts/              # Setup, QA, evidence and lifecycle orchestration
├── tooling/typescript/   # Shared strict TypeScript presets
└── setup-config.json     # Declarative setup wizard contract
```

## CONVENTIONS

- Workspace aliases resolve package source directly; preserve `@jeomwon/*` subpath exports and TypeScript path mappings together.
- Both Next.js apps intentionally build with `next build --webpack`.
- Bun uses the hoisted linker. Biome uses spaces, organized imports, Tailwind directives, and project-specific disabled rules.
- UI primitives are flat named exports with `data-slot`; add `"use client"` only to interactive components. `globals.css` scans both app source trees.
- Email exposes one `./reservation` module. Keep its discriminated kind union exhaustive, readonly contracts, `.js` relative suffixes, and inline email-safe styles.
- Tests follow three homes: backend tests in `packages/backend/tests/`, component tests beside app components, script contract tests beside scripts.

## ANTI-PATTERNS

- Do not hand-edit `convex/_generated/`, `.next/`, `.react-email/`, `qa-artifacts/`, build caches, or installed dependencies.
- Do not put Convex, agent, chat, storage, or event-bus runtime into `apps/web`.
- Do not hardcode a domain pack's proper nouns in template source; update injection inputs/outputs.
- Do not bypass typed `packages/backend/src` contracts with ad hoc raw function references or unnormalized Node-to-Convex values.
- Do not broaden feature work into plugin infrastructure unless repeated use proves the abstraction.
