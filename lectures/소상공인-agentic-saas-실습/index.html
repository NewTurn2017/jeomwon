06 · OWNERSHIP

Next.js·Convex·Vercel은 무엇을 맡나

NEXT.JS · SURFACE

두 개의 제품 화면

  • Public Web: 소개·유입
  • App: 고객·운영자·채팅
  • 각각 독립 root와 배포
CONVEX · TRUTH

데이터와 서버 규칙

  • reactive query
  • transactional mutation
  • scheduler와 durable state
VERCEL · DELIVERY

두 Next 앱의 배포

  • Web project
  • App project
  • Convex는 별도 deployment

한 저장소라고 한 번에 원자적으로 배포되는 것은 아닙니다. [R6-R10]

Next.js는 화면, Convex는 데이터와 서버 규칙, Vercel은 두 Next.js 앱을 배포합니다. Web과 App은 독립 프로젝트이고 Convex는 별도 deployment입니다. 세 단위의 롤아웃은 원자적이지 않으며 환경 변수와 배포 키도 각각 확인합니다. [C2][R6-R10]

held의 유효한 취소는 즉시 cancelled, 수용량 반환 confirmed/rescheduled가 취소창 안이면 escalated, 수용량 유지 threadId는 라우팅 문맥일 뿐 신원·권한이 아님

[C3] · R14

최종 보장은 mutation이 담당합니다. held 예약을 유효하게 취소하면 cancelled로 바뀌고 수용량을 돌려줍니다. confirmed 또는 rescheduled 예약을 취소창 안에서 취소하면 escalated로 바뀌고 수용량을 유지합니다. threadId는 라우팅 문맥이며 신원이나 권한이 아닙니다. [C3][R14]
